## 計測で分かったこと

- 生成済み範囲を飛ぶ条件 (explorer 8 体, 20 b/s) で Kodama はチャンク遅延 平均 -21%、p99 -27%。効いているのは先読みと背後保持。進行方向優先は差が出ていない
- 未生成地帯を飛ぶ条件では生成能力が上限で、Paper と差が出ない
- 帯域は Gale の無駄な移動パケット削減で約 -22%
- 事前生成をプレイヤーがいる間に動かすと MSPT が悪化する (同時 2 件でも p99 が大きく悪化) ため、既定は 0 (オンライン中は停止)
- Mob LOD の中距離を Paper の EAR 範囲 (32) の外に置くと Paper より遅くなる。既定は near 16 / far 32 にした
- ticking 昇格を 1 tick あたり 4 チャンクに分散すると、50ms 超えの tick が無くなる。代わりに p99 は 20ms 前後になる (Paper は 10ms 前後だが、まとめてスパイクを出す)
- settler 8 体を 3 周 (平均): Paper 3.95 / Kodama 3.99 ms。p99 の悪化 (12.9 → 15.7) は chunk-loading が原因で、代わりに max が 72 → 40 ms、50ms 超えが 0 になる。mob-lod、async、safe プリセットはどれも平均に差が出ない
- mixed 20 体で JFR を取ると、メインスレッドの内訳はエンティティ 15% (うち Mob AI 3%)、新規チャンクの `postProcessGeneration` で走る流体 tick 18%、`NaturalSpawner` 12〜16%、チケットの期限切れ処理 3〜8%
- Paper の `ChunkCoordinate` など 4 クラスの `hashCode` は `(int) HashCommon.mix(key)` で、`ConcurrentHashMap` の spread と打ち消し合い、バケットが chunkX だけで決まっていた (3600 チャンクで 8192 中 60 バケット)。`0024` で解消
- Paper のチケット期限は毎 tick 全件を減算する。Kodama の先読み・unload 遅延チケットで 3% → 8% に増えていたため、`0025` で期限なしチケット＋自前の期限管理 (1 秒ごと) にした
- 上の 2 本の後、mixed 20 体 3 周で Paper 比 MSPT 平均 -11〜-23%、p99 -28〜-43%、50ms 超えの tick -70%
- JFR の内訳は `jfr print --stack-depth 200` で取り直した (既定は 5 フレームで切れ、包含の割合が過小になる)。mixed 20 体でメインスレッドのサンプル数は Paper 2378 / 修正前 Kodama 2166 / `0026`-`0029` 後 1329。流体後処理は 575 / 466 / 171 サンプル
- 残りの大きいものは `NaturalSpawner` (17%、ランダム位置のブロック参照と乱数でバニラ由来) とエンティティ tick (18%)。保存の pack はサーバー停止時の全保存で、プレイ中には出ない
- 未生成地帯を飛ぶ explorer 8 体 (2 周): `0034` でチャンク遅延 平均 -44%、p99 -38〜-47%、実効速度 2 倍、MSPT p99 -41%。ワーカーは Paper 2 本 + 予備 3 本
- ホッパー休眠: 15 シナリオで Paper と転送 tick が完全一致。待機ホッパー 2000 個で MSPT 平均 -35%、最大 -82%
- GUI (`npm run gui`) 42 項目、赤石 (`npm run redstone`) 16 項目、プラグイン互換 (`npm run plugins`) 全項目合格
- 遅い回線の模擬 (ボットのソケット読み取りを 20 秒止める) で、送信待ちは保留なし 3.3MB / 保留あり 2.2MB。回復後 10 秒で圧縮レベルが元に戻る

## 設計から外した判断

- §2.3 送信パケットキャッシュは「シリアライズ＋圧縮済みバイト列」ではなくパケットオブジェクトの共有にした。バイト列方式は Netty のエンコーダーと圧縮器を迂回する必要があり ViaVersion と衝突する。圧縮はメインスレッド外なので、計測で必要になってから検討する
- §2.5 事前生成は、プレイヤーがいる間は既定で停止 (上記の計測結果による)
- §1 Mob LOD の中距離は物理をバニラのまま動かすため、Paper の EAR より重くなる範囲には置かない
- §1 Mob LOD 第2段階 (遠距離の座標シミュレーション・SoA・デスポーン換算・復元分散) は見送り。Mob AI はメインスレッドの 3〜5% で、第1段階も settler で MSPT に差が出なかった。湧き・デスポーンの統計をバニラから外す危険に見合わない
- Leaf 0041 Multithreaded Tracker と 0083/0084 は見送り。トラッカーは mixed 60 体でもメインスレッドの 5.1% で、0041 はメインスレッド外から呼ばれたイベントを後回しで実行するため、プラグインのキャンセルが効かなくなる
